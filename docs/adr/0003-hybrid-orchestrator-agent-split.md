# Hybrid orchestrator/agent split for Fix Attempts

A Fix Attempt has ~9 steps from "Sentry Issue picked up" to "PR opened". We considered Big Agent (Claude does everything including git + push + `gh pr create`), Narrow Agent (orchestrator extracts file edits from Claude via a structured output), and Hybrid (orchestrator owns git scaffolding + push + PR creation; Claude owns code edits + local commits). We chose **Hybrid** because (a) live-logs UX needs structured lifecycle events ("cloning", "running Claude", "pushing", "opening PR") which Big Agent obscures inside its tool-call stream, (b) the GitHub token stays out of Claude's environment — only the orchestrator handles GitHub API auth, (c) Claude uses its normal tool surface (Read/Edit/Write/Grep/Bash) without being constrained to a structured output format, and (d) Claude writing the commit message itself keeps the message co-located with the change author. The cost is more orchestrator code than Big Agent, but it's the boring mechanical kind.
