# TypeScript over Python for the entire stack

The app has three components: a Claude agentic worker, an HTTP/SSE backend, and a web UI. Agentic AI work is conventionally Python, so the obvious split would be Python worker + JS UI. We chose **TypeScript end-to-end** (`@anthropic-ai/claude-agent-sdk`, Hono backend, React UI, shared types package) because (a) the maintainer is not fluent in Python — building an unfamiliar-language worker for a non-trivial app would slow everything down and skew architectural choices, (b) the TS Agent SDK has feature parity with the Python one for our use case, and (c) one language across worker + backend + UI gives us shared types and a single build/dev/runtime story. The cost is going against the AI-tooling current; the benefit is a stack the maintainer can actually move fast in.
